# 验证优先

任何大规模任务都先做小批验证。

## 为什么先验证

- 能尽早发现文件格式和字段映射错误
- 能尽早验证 HDFS 路径和外表定义
- 能尽早发现 SQL 逻辑是否可跑通
- 能避免全量生成后才发现链路不通

## 小批验证最小步骤

1. 生成少量维表和事实表样本
2. 上传到 HDFS 测试路径
3. 建外表或导入测试内表
4. 执行最小读回 SQL
5. 执行核心任务 SQL 或缩小版 SQL
6. 核查行数、空值、主外键和结果可读性

## 通过标准

- 外表可读
- 内表可装载
- 读回字段正确
- 关键 SQL 可执行
- 结果规模和分布基本符合预期

## 放大全量前必须锁定

- 文件格式
- 分区策略
- 单批大小
- HDFS 目录规则
- 外表和内表定义
- checkpoint 规则
