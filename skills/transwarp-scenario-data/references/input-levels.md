# 输入等级

先判断用户给到的信息强度，再决定能推进到什么深度。

## Level 0

只有场景描述，没有结构化材料。

典型输入：

- “帮我复现某银行日终跑批场景。”
- “我要在星环测试集群上复现某监管离线数仓。”

处理原则：

- 先问关键边界，不要直接产出最终脚本。
- 可以给假设版方案，但要标注假设。
- 不要伪装成已经掌握真实表结构。

## Level 1

提供了 DDL、字段清单或建表说明。

处理原则：

- 解析字段、类型、分区键、分布键、桶数、压缩信息。
- 识别缺失的维表、主表、桥表和字典表。
- 任何补全出的表或字段都要说明依据。

## Level 2

提供了 SQL、Shell、调度脚本或批处理逻辑。

处理原则：

- 反推源表、目标表、关联路径和批处理窗口。
- 识别 join、filter、聚合、去重、排序和压缩意图。
- 反推最小可运行数据模型。

## Level 3

提供了统计信息。

典型信息：

- 基数
- 空值率
- Top-K
- 直方图
- 行数
- 分区大小

处理原则：

- 统计信息优先级高于行业常识假设。
- 用统计信息驱动数据分布、热点、空值和长尾设计。
- 如走 SDV 或混合模式，用统计信息修正默认参数。

## Level 4

提供了样本数据。

处理原则：

- 先做样本质量检查，再决定是否适合拟合。
- 优先保留主外键、时间特征、状态分布和金额边界。
- 只有样本质量足够时，才考虑 SDV 增强。

## 升级规则

- 一旦出现更强输入，就按更高等级处理。
- 脚本证据优先级高于口头描述。
- 对 Level 0 和 Level 1，如果用户要求完整可执行方案，先输出带假设标记的版本，再列出补齐清单。
