# 任务优先建模

先从现场 SQL、DDL、调度逻辑反推任务依赖，再定义最小必要表集。

## 为什么必须先做这一步

如果先按行业经验补表，很容易出现：

- 表铺得太大，但真正任务根本用不到
- 造出来的字段与任务 SQL 不对齐
- join 键、filter 字段、partition 字段缺失
- 目标表列顺序和任务输出对不上

## 标准顺序

1. 读取任务 SQL 或调度逻辑
2. 列出源表、目标表、中间表
3. 抽取 select 字段
4. 抽取 join 键和 join 类型
5. 抽取 filter 条件
6. 抽取 group by、聚合字段、排序字段
7. 抽取分区字段和目标分区值
8. 再判断哪些维表、事实表、桥表是最小必要集合

## 需要显式检查的内容

- 目标表每一列是否都能从任务 SQL 映射出来
- 每个 join 键是否在左右表都存在
- join 键类型是否兼容
- where 条件涉及的字段是否可造
- partition 字段是否存在且能在外表、内表、任务 SQL 中对齐

## 默认行为

- 先做任务依赖分析，再做行业补全
- 如果用户没有给 SQL，只给场景描述，才退回领域蓝图补全
- 一旦拿到真实 SQL，真实 SQL 的证据优先级高于行业猜测
